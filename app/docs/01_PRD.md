## 2. 제품 개요

### 2.1 제품명 및 한 줄 정의

**올케어안전플랫폼**: 나라장터(및 개별 발주처) 공고 기반으로 건설사가 안전보건관리계획서를 조회·자동작성·다운로드할 수 있는 SaaS 플랫폼 (constitution.md 제목, SPEC-001 Input)

### 2.2 문제 정의

- 건설사 담당자는 입찰에 참여할 때마다 발주처별로 요구 양식이 다른 안전보건관리계획서를 매번 처음부터 작성해야 하며, 공고 내용을 발주처 웹사이트에서 수기로 확인해야 한다.
- 공고마다 안전보건관리계획서 샘플이 첨부되어 있지 않은 경우가 많아, 어떤 양식을 써야 할지 판단하는 데도 시간이 든다(constitution.md Principle V 배경).
- 발주처마다 오픈API 인증 체계·응답 필드·낙찰 확정 정보 제공 범위가 달라, 여러 공공기관의 공고를 한 곳에서 동일한 기준으로 모아 보기 어렵다.

### 2.3 가치 제안

- **Discover**: 나라장터/방위사업청/한전/도로공사 등 여러 발주처의 실 공고를 한 화면에서 검색·필터링
- **Automate**: 공고 첨부 샘플 → 발주처 표준 양식 → 범용 기본 양식 → 회원 업로드 순의 폴백 체인으로, 어떤 공고를 골라도 항상 계획서 작성을 시작할 수 있음(constitution.md Principle V)
- **Assist**: 위험성평가 항목·사업개요를 첨부 문서에서 AI로 자동 추출(FR-026, `extract-risk-items`/`extract-business-overview`)
- **Deliver**: 완성된 계획서를 PDF/DOCX로 즉시 다운로드(FR-011)

### 2.4 대상 플랫폼

반응형 웹, Mobile First (constitution.md 문서 헤더)

## 4. 목표 및 성공 지표

SPEC-001 Success Criteria(SC-001~SC-008) 기준의 정량 목표를 그대로 채택한다:

| 지표 | 목표 |
|---|---|
| 회원가입 → 첫 공고 검색 결과 확인 | 5분 이내 (SC-001) |
| 다른 회원 데이터 무단 접근 차단율 | 100% (SC-002) |
| 공고 선택 → 계획서 단계별 작성 완료 | 10분 이내 (SC-003) |
| 다운로드 요청 → 파일 제공 | 10초 이내 (SC-004) |
| 신규 발주처 API 등록 → 검색 결과 반영 | 5분 이내 (SC-005) |
| 비회원의 보호 화면 접근 시 로그인 안내 전환율 | 100% (SC-006) |
| 답변 완료된 문의의 무단 수정·삭제 차단율 | 100% (SC-007) — **[미구현]** InquiriesPage가 Mock 데이터로만 동작해 현재 측정 불가 (SRS Appendix C §2.5) |
| 계획서 작성 화면 일관성 만족도 | 90% 이상 (SC-008) |

**비즈니스 지표(신규, 코드 기반 역산)**:
- 월간 구독 전환율(구독 `pending`→`active` 전환 비율), 무통장입금 확인 소요 시간(관리자 액션 기준), 쿠폰 상환율(발급 대비 `used` 비율) — 현재 대시보드(`AdminDashboardPage`)에는 회원/계획서/공고/문의 카운트만 있고 구독·결제·쿠폰 관련 KPI는 노출되지 않는다 `[결정 필요: AdminDashboardPage에 구독/결제 지표 추가 여부]`

## 8. 제약사항 및 원칙 (요약, constitution.md 전문 참조)

- 메인페이지 기준선을 임의로 변경하지 않는다(Principle I).
- spec.md/plan.md/tasks.md에 명시되지 않은 기능을 임의로 추가하지 않는다(Principle II) — 단, 위 §5에서 확인된 "스펙에 없는데 이미 구현된 기능"(대표이사 필드, 관리자 승격)은 사후 스펙 정합화가 필요한 예외 사례로 별도 관리한다.
- 신규 화면도 기존 디자인 토큰·컴포넌트 패턴을 재사용한다(Principle III).
- 모든 TASK는 요구사항 ID와 디자인 근거를 인용해야 한다(Principle IV).
- 나라장터 등 발주처 연동은 실제 API·실키 기준이며, 양식/낙찰판단 폴백 체인을 따른다(Principle V).
