# 올케어안전플랫폼 PROJECT SCOPE v1.0

> 기준 문서: `docs/01_PRD.md`, `docs/02_SRS_BASELINE.md`, 레거시 구현체(`C:\AI_SERVICE\acplatform` 루트, React/Vite/Supabase, `src/pages/*`), 현재 재구축 대상(`app/`, Next.js 16 + React 19 + Tailwind 4).
>
> 목적: PRD/SRS가 정리한 "무엇을, 왜"를 기준으로, 이 저장소(`app/`)에서 **직접 구현할 범위(IMPLEMENT)**와 **만들지 않을 범위(EXCLUDED)**를 확정한다. PRD/SRS에 남아있던 `[결정 필요]` 항목은 본 문서에서 최종 결정한다 — 더 이상 열린 질문으로 남기지 않는다.
>
> 작성일: 2026-09-12 · 상태: Approved (구현 착수 기준)

## 1. 전제: 현재 상태

- `app/` 디렉터리는 `create-next-app` 스캐폴드 그대로이며(`src/app/page.tsx`가 기본 템플릿), 실제 기능은 아직 이식되지 않았다.
- 실제로 동작하는 기준 구현은 레거시 저장소(React 18 + Vite + Supabase, `src/pages/*`, `supabase/functions/*`)이며, PRD §5/SRS §6의 "구현 상태"는 이 레거시 코드베이스를 조사한 결과다.
- 본 문서의 IMPLEMENT 항목은 **"레거시에 있는 기능을 Next.js(`app/`)로 재구현"**을 의미하고, EXCLUDED 항목은 **"레거시에 있어도 `app/`에는 가져오지 않음"** 또는 **"레거시에도 없고 앞으로도 만들지 않음"**을 의미한다.
- 스택 변경(Vite → Next.js App Router)에 따른 구현 방식 차이는 각 항목의 "구현 방식"에 명시한다.

| PG(결제대행사) 대체/추가 도입 | 토스페이먼츠로 이미 확정된 의사결정, 대체 도입은 별도 프로젝트 성격 |

| 발주처별 세부 오픈API 명세서 원문 재작성 | 각 발주처 공식 문서가 원 소스이며 본 프로젝트는 요약만 인용 |

## 4. 신규 발주처 API 추가 시 공통 절차 (참고)

새 발주처 인증키가 발급되면(project memory: 신규 발주처 API 추가 절차):
1. `fetchXxx` 형태로 동기화 함수 작성 → 낙찰판단 폴백 3단계(①낙찰자 확정 → ②개찰결과 1순위 → ③마감일) 중 지원 가능한 단계를 코드 주석에 명시
2. Edge Function/Route Handler 배포
3. `AdminApiSyncPage`에서 수동 동기화 실행 → `announcements` 반영 및 `sync_log` 기록 검증
4. 배포 후 실제 응답 200 확인 전까지 회원 화면에는 노출하지 않음(EX 사례처럼 404 방치 방지)
