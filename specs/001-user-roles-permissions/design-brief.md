## 0. 서비스명 반영 지시 (중요)

기존에 게시된 메인 페이지 시안(`design/main-page/Main.dc.html`)은 임시 서비스명 **"세이프닥
(SafeDoc)"** 으로 제작되었다. 이번 기능부터 공식 서비스명은 **"올케어안전플랫폼"** 으로 확정한다.

- 헤더 로고 텍스트, 파비콘 옆 서비스명, 히어로 문구, 푸터 회사/서비스명 등 **"세이프닥"이 등장하는
  모든 위치를 "올케어안전플랫폼"으로 교체**해야 한다.
- 로고 아이콘(방패+체크) 등 텍스트가 아닌 브랜드 요소는 기준선 그대로 유지한다(별도 지시 전까지
  로고 심볼 자체는 변경하지 않는다).
- 이 문서 이후의 모든 화면 지시에서 서비스명은 "올케어안전플랫폼"으로 표기한다.

## 1. 서비스 개요

건설사의 공무·업무 담당자가 나라장터 등 공공조달 공고를 조회하고, 각 발주처가 요구하는 안전보건관리
계획서를 공고별 요구 항목에 맞춰 단계별로 작성한 뒤 PDF·DOCX로 다운로드하는 B2B SaaS다. 비회원·회원·
관리자 세 종류의 사용자가 있으며, 구독(유료) 기반으로 운영된다.

**핵심 가치**: 공고마다 다른 안전보건관리계획서 요구 항목을 자동으로 파악하고, 실제 공공데이터 API로
가져온 실 공고문을 기준으로 계획서 작성을 자동화한다.

---

## 2. 디자인 기준선 (Constitution Principle I·III)

기존 메인 페이지 시안(`design/main-page/Main.dc.html`)을 화면 설계의 공식 기준선으로 삼는다. 신규
화면은 아래 기준을 반드시 재사용해야 하며, 벗어날 경우 이 문서 또는 화면별 설계 산출물에 사유를
기록한다.

- **색상 토큰**: 네이비 계열 프라이머리(헤더, 주요 텍스트, 배지 배경) + 앰버 계열 액센트(주요 CTA
  버튼, 진행률, 강조 배지). 성공/경고/위험 상태 색상(초록/앰버/빨강 계열)도 기존 정의를 재사용한다.
- **타이포그래피**: 헤드라인은 세리프 계열(Noto Serif KR), 본문·UI 텍스트는 산세리프 계열(Noto Sans
  KR)로 구분해 사용한다.
- **컴포넌트 패턴**: 카드(둥근 모서리, 옅은 테두리, 은은한 그림자), 상태 배지(카테고리·D-day·첨부
  여부), 프라이머리/세컨더리 버튼 스타일, 진행률 바, 탭 전환 UI를 기존 메인 페이지와 동일한 형태로
  재사용한다.
- **유지해야 할 핵심 인터랙션 패턴**:
  - 검색창 + 카테고리 필터 조합
  - 카드 리스트(항목당 배지 2~3개 + 액션 버튼 1개)
  - 다단계 마법사(상단 스텝 인디케이터 + 본문 + 하단 이전/다음 버튼)
  - 탭 전환(문서함의 "작성중/완료" 같은 좌우 토글 탭)
  - 모달 오버레이(작성 마법사 등 몰입형 흐름)

## 3. 사용자 역할과 권한

| 역할 | 정의 | 접근 가능 범위 |
|---|---|---|
| 비회원 | 로그인하지 않은 방문자 | 메인 페이지(공개 영역)만 열람 가능. 보호된 화면 접근 시 로그인 안내로 전환 (FR-003) |
| 회원 | 가입·로그인한 건설사 담당자 | 본인이 작성한 계획서·문의만 조회·수정·삭제 가능 (FR-004). 구독 중일 때만 핵심 기능 접근 가능 (FR-015) |
| 관리자 | 운영자가 사전 발급한 계정으로 로그인 (FR-020) | 회원 관리(FR-012), 발주처별 API 인증정보 관리(FR-007, FR-013), 구독 결제창 관리(FR-014), 문의 답변(FR-017) |

공통 규칙: 회원은 다른 회원이 작성한 계획서·문의를 조회·수정·삭제할 수 없다(FR-004). 관리자가 답변을
등록한 문의는 작성자 회원이 더 이상 수정·삭제할 수 없다(FR-018).

```
│       └─ 계획서 작성 마법사 (다단계)
├─ 내 문서함 (작성중 / 완료 탭)

└─ 관리자
    ├─ 관리자 로그인 (일반 로그인과 분리된 경로)
    ├─ 관리자 대시보드
    ├─ 회원 관리
    ├─ 발주처별 API 인증정보 관리 (연동 상태·로그 포함)
    ├─ 구독료 결제창 관리
    └─ 문의 관리·답변
```

## 5. 화면별 상세 지시

각 화면은 "목적 / 주요 구성요소 / 상태 / 권한 / 관련 요구사항"으로 기술한다. 실제 배치·문구는 Claude
Design 작업 시 기준선 패턴(2장)을 따라 구체화한다.

### 5.1 메인 페이지 (공개)
- **목적**: 서비스 소개, 공고 검색 진입점, 회원가입 유도.
- **구성요소**: 기존 시안 구조 그대로(헤더, 히어로+검색, 공고 리스트 미리보기, 이용방법 4단계, 특징
  하이라이트, 내 문서함 미리보기 위젯, CTA, 푸터) 유지, 서비스명만 교체.
- **권한**: 비회원 포함 전체 공개. 단, 실제 공고 리스트/내 문서함 위젯은 로그인 여부에 따라 "샘플
  미리보기"와 "실 데이터"를 구분해 보여줄 수 있다.
- **근거**: Constitution Principle I(기준선), Principle III(일관성).

### 5.2 로그인 안내 (Guard 화면)
- **목적**: 비회원이 보호된 화면에 딥링크 등으로 접근했을 때 실제 콘텐츠 대신 표시.
- **구성요소**: 안내 메시지, 로그인 버튼, 회원가입 버튼. 원래 가려던 화면의 실제 내용은 절대 노출하지
  않는다.
- **권한**: 비회원 전용 진입.
- **근거**: FR-003, SC-006.

### 5.3 로그인
- **목적**: 회원 로그인.
- **구성요소**: 이메일, 비밀번호 입력, 로그인 버튼, 회원가입 링크, (관리자 로그인은 별도 경로 —
  5.14 참고).
- **근거**: FR-002.

### 5.4 회원가입
- **목적**: 신규 회원 등록.
- **구성요소**: 이메일, 비밀번호, 소속 건설사명, 사업자등록번호, 담당자명, 연락처 — 6개 필드 모두
  필수 입력. 하나라도 비면 가입 완료 버튼 비활성화 또는 오류 표시.
- **근거**: FR-001 (Clarification: 회원가입 필수 필드).

### 5.5 공고 검색·목록 (회원 전용)
- **목적**: 등록된 발주처의 실 공고 검색·열람.
- **구성요소**: 검색창(공고명·발주기관·공고번호), 카테고리 필터, 공고 카드 리스트(발주처, 마감일
  D-day, 첨부 서식 유무 배지, "계획서 작성 시작" 버튼).
- **범위**: 회원과 관리자는 등록된 발주처의 **전체 공고를 동일한 범위**로 본다. 관리자 화면에는 추가로
  각 발주처 API의 연동 상태(성공/실패)와 마지막 조회 시각이 함께 표시된다 (5.17 참고).
- **상태**: 공고 없음(빈 상태), API 응답 실패 시 오류 안내(서비스 전체 중단 없이).
- **근거**: FR-005, FR-006, FR-023 (Clarification: 목록 범위), US2.

### 5.6 공고 상세
- **목적**: 선택한 공고의 상세 정보와 첨부된 안전보건관리계획서 샘플·표준 양식 확인.
- **구성요소**: 발주처, 공고번호, 마감일, 공사분야, 첨부 양식 목록, "계획서 작성 시작" CTA.
- **상태**: 샘플·표준 양식이 첨부되지 않은 공고의 경우, 양식 미확인 안내와 수동 확인 대체 경로 제시.
- **근거**: FR-006, Edge Case(양식 미첨부).

### 5.7 안전보건관리계획서 작성 마법사
- **목적**: 공고가 요구하는 항목에 맞춘 단계별 계획서 작성.
- **구성요소**: 상단 스텝 인디케이터 (Phase 1 기준: 정확히 4단계, "1/4"~"4/4" 표시), 단계별 입력 폼, 이전/다음 버튼, 진행 상태 저장 표시. 향후(Phase 2+) 공고별 요구 항목이 달라지면 단계 수가 가변적으로 변할 수 있도록 설계.
- **일관성 요구**: 모든 단계는 메인 페이지 및 서로 간에 동일한 레이아웃·컴포넌트 스타일을 유지해야
  한다(카드, 배지, 버튼, 여백, 색상 토큰 동일).
- **상태**: 중단 후 재접속 시 이전 입력값과 진행 단계 복원. 자동 저장은 15초 간격, 세션 만료 시 마지막 저장 지점부터 재개.
- **근거**: FR-008, FR-009, FR-010, US3, Clarification: 마법사 단계 가변성.

### 5.8 내 문서함
- **목적**: 작성중·완료된 계획서 목록 관리.
- **구성요소**: "작성중 / 완료" 탭, 작성중 항목은 진행률 표시, 완료 항목은 다운로드 진입점 표시.
- **권한**: 본인이 작성한 항목만 노출(FR-004).
- **근거**: FR-010, FR-011, US4.

### 5.9 다운로드 옵션
- **목적**: 완성된 계획서를 PDF 또는 DOCX로 선택 다운로드.
- **구성요소**: PDF 다운로드 버튼, DOCX 다운로드 버튼, 다운로드 완료 안내.
- **근거**: FR-011, SC-004.

### 5.10 마이페이지
- **목적**: 회원 본인 정보 확인, 구독 상태 확인.
- **구성요소**: 가입 정보(회사명, 담당자명, 연락처 등) 조회, 구독 상태(활성/만료) 및 만료일 표시.
- **근거**: Key Entity 회원·구독.

### 5.11 구독·결제 안내
- **목적**: 미구독 회원이 핵심 기능(공고 검색, 계획서 작성, 다운로드 등)에 접근을 시도할 때 표시.
- **구성요소**: 구독 안내 메시지, 구독 신청/결제 진입 버튼.
- **근거**: FR-015, US6 (Clarification: 구독은 서비스 전체 이용 기준).

### 5.12 문의하기 (목록·작성)
- **목적**: 회원이 1:1 문의(질문)를 작성하고 본인 문의 목록을 확인.
- **구성요소**: 문의 작성 폼, 본인 문의 목록(답변 대기/답변 완료 상태 배지).
- **권한**: 본인 문의만 조회 가능(FR-004).
- **근거**: FR-016, US7.

### 5.13 문의 상세
- **목적**: 문의 내용과 관리자 답변 확인.
- **구성요소**: 질문 내용, 답변 내용(있는 경우), 수정/삭제 버튼.
- **상태**: 관리자 답변이 등록된 이후에는 수정/삭제 버튼이 비활성화되고 "답변 완료로 수정·삭제할 수
  없습니다" 같은 잠금 안내를 표시해야 한다.
- **근거**: FR-018, FR-019, US7.

### 5.14 관리자 로그인
- **목적**: 관리자 전용 로그인 경로. 일반 회원 로그인 화면과 시각적으로 구분되어야 한다(예: 별도
  URL/화면, "관리자" 라벨 명시).
- **근거**: FR-020 (Clarification: 관리자 계정은 사전 생성, 일반 가입과 분리).

### 5.15 관리자 대시보드
- **목적**: 관리자 기능으로의 진입점 요약(회원 수, 미답변 문의 수, API 연동 상태 요약 등).
- **근거**: US5, US6, US7 통합 진입점.

### 5.16 회원 관리
- **목적**: 전체 회원 목록 조회 및 계정 상태(정상/정지 등) 관리.
- **구성요소**: 회원 목록 테이블(회사명, 담당자명, 가입일, 구독 상태, 계정 상태), 상태 변경 액션.
- **근거**: FR-012.

### 5.17 발주처별 API 인증정보 관리
- **목적**: 발주처 단위 공공데이터 API 인증 정보 등록·관리.
- **구성요소**: 발주처 목록, 각 발주처별 인증키 등록/수정/삭제 폼, **최근 연동 상태(성공/실패)와
  마지막 조회 시각 표시**(Clarification 반영).
- **주의**: 인증키 값 자체를 평문으로 노출하지 않는 마스킹 처리 필요(FR-021).
- **근거**: FR-007, FR-013, FR-021, FR-023.

### 5.18 구독료 결제창 관리
- **목적**: 구독 결제 수단·조건 설정.
- **구성요소**: 결제 수단 설정, 구독 조건(가격, 주기) 설정, 결제 이력 조회.
- **근거**: FR-014.

### 5.19 문의 관리·답변
- **목적**: 관리자가 전체 회원 문의를 확인하고 답변 작성.
- **구성요소**: 전체 문의 목록(답변 대기/완료 필터), 답변 작성 폼.
- **근거**: FR-017.

### 5.20 모바일 내비게이션 (공통 패턴)
- **목적**: 좁은 화면(모바일 폭)에서 상단 내비게이션 접근성 확보.
- **구성요소**: 헤더에는 로고와 주요 CTA만 상시 노출, 햄버거 아이콘 탭 시 드로어(또는 오버레이)로
  전체 메뉴(공고검색, 내 문서함, 이용방법, 마이페이지 등) 노출.
- **근거**: FR-022 (Clarification: 모바일 내비게이션 패턴).

## 10. Claude Design 작업 지시사항

1. **코드 작성 금지**: 이 단계에서는 React 컴포넌트나 CSS를 작성하지 않는다. 화면 구조, 콘텐츠 배치,
   상태 정의까지만 다룬다.
2. **기준선 우선 확인**: 작업 시작 전 기존 게시 아티팩트(`design/main-page/Main.dc.html` 및 게시된
   URL)를 반드시 참고해 색상·폰트·컴포넌트 패턴을 그대로 재사용한다.
3. **서비스명**: 모든 화면에서 "올케어안전플랫폼"으로 표기한다(0장 참고).
4. **다음 단계**: 이 브리프가 승인되면 화면별 저해상도(와이어프레임) 목업 → 고해상도 목업 순으로
   진행하며, 이때 비로소 `.dc.html` 마크업 작성이 시작된다.
