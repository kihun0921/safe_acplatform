# Feature Specification: 회원·관리자 권한 기반 안전보건관리계획서 작성 플랫폼

**Feature Branch**: `001-user-roles-permissions`

**Created**: 2026-08-29

**Status**: Draft

**Input**: User description: "안전보건관리계획서작성 자동화프로그램을 만들고 싶다. 목표: 사용자는 실공고문을 나라장터 API인증값으로 가져올 수 있어야 한다 / 사용자는 각 발주처에서 요구하는 샘플양식 및 표준양식으로 안전보건관리계획서를 작성할 수 있어야 한다. 핵심 화면: 먼저 만들어준 메인 화면을 유지하되, 세부 안전보건관리계획서 단계마다 비슷한 패턴의 UI를 유지. 사용자: 비회원-회원-관리자. 회원기능: 회원가입-로그인/로그아웃-계획서 작성-완료된 계획서 다운로드. 관리자 기능: 로그인-회원관리-발주처별 오픈 API 입력-구독료 결제창 관리. 권한: 회원은 다른 회원의 작성내용을 조회·수정·삭제할 수 없다 / 일반 회원은 관리자 답변을 작성할 수 없다 / 관리자가 답변한 이후 회원은 질문을 수정·삭제할 수 없다 / 비회원이 보호된 화면에 접근하면 로그인 안내를 보여준다."

## Clarifications

### Session 2026-08-29

- Q: 모바일 화면에서 "공고검색 / 내 문서함 / 이용방법" 같은 상단 내비게이션 메뉴를 어떤 방식으로 노출할까요? → A: 헤더의 로고·CTA는 유지하고, 햄버거 아이콘을 탭하면 드로어/오버레이로 전체 내비게이션 항목을 노출한다.
- Q: 회원가입 시 이메일·비밀번호 외에 어떤 정보를 필수로 입력받아야 할까요? → A: 이메일, 비밀번호, 소속 건설사명, 사업자등록번호, 담당자명, 연락처를 모두 필수로 입력받는다.
- Q: 나라장터에서 가져온 공고 목록을 화면에 보여줄 때, 일반 회원과 관리자가 보는 범위를 각각 어떻게 정의해야 할까요? → A: 회원과 관리자 모두 등록된 발주처의 전체 공고를 동일한 범위로 보되, 관리자 화면에는 각 발주처 API의 연동 상태·로그가 추가로 표시된다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원가입과 로그인으로 서비스 이용 시작 (Priority: P1)

건설사의 공무직원이 서비스를 처음 이용하기 위해 회원가입을 하고, 로그인하여 보호된 기능(공고 조회, 계획서 작성 등)에 접근한다. 비회원 상태로 보호된 화면에 접근하면 로그인 안내를 받는다.

**Why this priority**: 회원 식별과 접근 제어는 이후 모든 기능(계획서 작성 내용 보호, 다운로드, 문의 등)의 전제 조건이다. 이것이 없으면 다른 어떤 기능도 안전하게 제공할 수 없다.

**Independent Test**: 비회원 상태로 보호된 화면에 접근해 로그인 안내가 뜨는 것을 확인하고, 회원가입 후 로그인하여 동일 화면에 정상 접근할 수 있는지 검증하는 것만으로 완전히 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 방문자, **When** 계획서 작성 화면과 같은 보호된 화면에 직접 접근을 시도하면, **Then** 시스템은 로그인 안내 화면을 보여주고 보호된 화면의 실제 내용은 노출하지 않는다.
2. **Given** 아직 계정이 없는 방문자, **When** 이메일과 비밀번호로 회원가입을 완료하고 로그인하면, **Then** 보호된 화면에 정상적으로 접근할 수 있다.
3. **Given** 로그인한 회원, **When** 로그아웃을 실행하면, **Then** 이후 보호된 화면 접근 시 다시 로그인 안내를 받는다.

### User Story 2 - 나라장터 실공고문 조회 (Priority: P1)

로그인한 회원이 등록된 API 인증값을 통해 나라장터에서 실제 입찰 공고문을 검색하고 열람한다.

**Why this priority**: 실제 공고 데이터 조회는 이 서비스의 핵심 가치(공고에 맞춘 계획서 자동화)가 성립하기 위한 필수 입력이다. 이 기능 없이는 계획서 작성 자체가 불가능하다.

**Independent Test**: 등록된 API 인증값으로 공고 검색을 실행해 실제 나라장터 공고 목록과 상세 정보(발주처, 마감일, 첨부 서식)가 조회되는지 확인하는 것만으로 완전히 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 공고명·발주기관·공고번호로 검색하면, **Then** 나라장터 API로 조회한 실제 공고 목록이 표시된다.
2. **Given** 조회된 공고 목록, **When** 회원이 특정 공고를 선택하면, **Then** 해당 공고의 상세 정보와 첨부된 안전보건관리계획서 샘플·표준 양식 정보가 표시된다.
3. **Given** 나라장터 API가 일시적으로 응답하지 않는 상황, **When** 회원이 공고를 검색하면, **Then** 시스템은 조회 실패를 명확히 안내하고 서비스 전체가 중단되지 않는다.

---

### User Story 3 - 발주처 맞춤 양식 기반 계획서 단계별 작성 (Priority: P2)

회원이 선택한 공고의 발주처가 요구하는 샘플·표준 양식에 맞춰, 기존 메인 화면과 일관된 UI 패턴을 유지하는 단계별 마법사를 통해 안전보건관리계획서를 작성한다.

**양식 우선순위 (폴백 체인)**:

공고마다 안전보건관리계획서 샘플이 첨부되어 있지 않으므로, 다음 우선순위를 따라 양식을 제공한다:

1. **공고 첨부 샘플 양식**: 나라장터 API에서 조회한 공고에 첨부된 안전보건관리계획서 샘플 파일이 있으면 이를 파싱해 필드 항목을 추출하고 사용한다.
2. **발주처 표준 양식**: 공고에 샘플이 없으면, 발주처별로 사전에 등록한 최적화된 기본 양식 템플릿을 사용한다. 발주처 정보는 나라장터 API 공고 상세에서 추출한다.
3. **범용 기본 양식**: 발주처 표준 양식도 없으면, 건설업 안전보건관리계획서의 일반적인 항목(공사개요, 안전관리 체계, 위험 요소, 대응 방안 등)을 포함하는 서비스 자체의 기본 양식을 사용한다.
4. **회원 샘플 업로드**: 위 세 경로 모두 불가능한 경우, 회원이 직접 양식 파일(PDF, DOCX, HWP 등)을 업로드하고, 시스템이 이를 파싱해 필드 항목을 추출해 마법사를 진행한다. 파싱에 실패하면 회원이 수동으로 항목을 입력하는 폴백을 제공한다.

**Why this priority**: 공고별 요구 항목에 맞춘 단계별 작성은 서비스의 핵심 기능이지만, 공고 조회(User Story 2)가 선행되어야 의미가 있다. 양식 다양성 대응은 서비스 활용 범위를 극대화한다.

**Independent Test**: 
- (샘플 있음) 첨부 양식이 있는 공고 선택 → 마법사 진행 → 공고 샘플이 반영됨 확인
- (샘플 없음) 첨부 양식이 없지만 발주처 표준 양식이 있는 공고 선택 → 기본 양식 사용 확인
- (모두 없음) 발주처 정보가 없는 공고 선택 → 범용 기본 양식 사용 확인
- 회원 업로드 모드: 직접 양식 파일 업로드 → 파싱 및 마법사 진행 확인

**Acceptance Scenarios**:

1. **Given** 안전보건관리계획서 샘플 양식이 첨부된 공고, **When** 회원이 "계획서 작성 시작"을 선택하면, **Then** 공고 첨부 샘플에서 추출한 항목이 반영된 단계별 작성 화면이 시작된다.
2. **Given** 샘플 양식이 없지만 발주처 표준 양식이 등록된 공고, **When** 회원이 "계획서 작성 시작"을 선택하면, **Then** 해당 발주처의 표준 양식 항목이 반영된 단계별 작성 화면이 시작된다.
3. **Given** 샘플과 발주처 표준 양식이 모두 없는 공고, **When** 회원이 "계획서 작성 시작"을 선택하면, **Then** 범용 기본 양식(공사개요, 안전 체계, 위험요소, 대응방안 등)이 반영된 단계별 작성 화면이 시작된다.
4. **Given** 모든 자동 양식 경로가 불가능한 상황, **When** 회원이 직접 샘플 파일을 업로드하면, **Then** 시스템이 파일을 파싱하고 필드 항목을 추출한 뒤 마법사를 시작한다. 파싱 실패 시 수동 입력 모드로 전환된다.
5. **Given** 작성 마법사의 여러 단계, **When** 회원이 단계를 이동하면, **Then** 각 단계는 메인 화면 및 이전 단계와 동일한 레이아웃·구성요소 스타일을 유지한다.
6. **Given** 작성 중인 계획서, **When** 회원이 일부 항목만 입력하고 중단했다가 다시 접속하면, **Then** 이전까지 입력한 내용과 진행 단계가 유지된 상태로 이어서 작성할 수 있다.

### User Story 4 - 완료된 계획서 다운로드 (Priority: P2)

회원이 작성을 완료한 안전보건관리계획서를 PDF 또는 DOCX 형식으로 다운로드한다.

**Why this priority**: 다운로드는 계획서 작성(User Story 3)의 최종 목적지이며, 이 기능이 있어야 회원이 실제로 입찰 서류 제출에 사용할 수 있다.

**Independent Test**: 작성이 완료된 계획서 하나를 대상으로 PDF와 DOCX 다운로드를 각각 실행해 파일이 정상적으로 생성·수령되는지 확인하는 것만으로 완전히 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 작성이 완료된 계획서, **When** 회원이 PDF 다운로드를 선택하면, **Then** 완성된 내용이 반영된 PDF 파일을 받는다.
2. **Given** 작성이 완료된 계획서, **When** 회원이 DOCX 다운로드를 선택하면, **Then** 동일한 내용이 반영된 DOCX 파일을 받는다.

### User Story 5 - 관리자의 회원 및 발주처 API 관리 (Priority: P3)

관리자가 로그인하여 전체 회원을 관리하고, 발주처별로 공고 조회에 필요한 API 인증 정보를 등록·관리한다.

**Why this priority**: 회원과 API 인증 정보 관리는 운영에 필수적이지만, 회원이 실제로 서비스를 이용하는 흐름(User Story 1~4)이 갖춰진 이후에 갖춰져도 서비스 검증에는 지장이 없다.

**Independent Test**: 관리자 계정으로 로그인해 회원 목록을 조회하고, 새로운 발주처의 API 인증 정보를 등록한 뒤 해당 발주처 공고가 검색에 반영되는지 확인하는 것만으로 완전히 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 로그인한 관리자, **When** 회원 관리 화면에 접근하면, **Then** 전체 회원 목록과 각 회원의 상태를 조회할 수 있다.
2. **Given** 로그인한 관리자, **When** 새로운 발주처의 API 인증 정보를 등록하면, **Then** 해당 발주처의 공고가 이후 공고 검색 결과에 포함된다.
3. **Given** 일반 회원, **When** 회원 관리 또는 API 인증 정보 등록 화면에 접근을 시도하면, **Then** 접근이 차단된다.

---

### User Story 6 - 구독료 결제 관리 (Priority: P3)

관리자가 안전보건관리계획서 서비스의 구독료를 징수할 수 있는 결제창을 관리하고, 회원은 구독 상태에 따라 서비스를 이용한다.

**Why this priority**: 수익화는 서비스 운영에 중요하지만, 핵심 사용자 가치 검증(User Story 1~4) 이후에 붙어도 무방한 비즈니스 계층이다.

**Independent Test**: 관리자가 결제창 설정을 등록하고, 구독하지 않은 회원 계정으로 유료 범위 기능에 접근을 시도했을 때 결제 안내가 표시되는지 확인하는 것만으로 완전히 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 로그인한 관리자, **When** 구독료 결제창 설정 화면에 접근하면, **Then** 결제 수단과 구독 조건을 설정·조회할 수 있다.
2. **Given** 구독하지 않은 회원, **When** 구독이 필요한 기능에 접근을 시도하면, **Then** 결제(구독) 안내 화면이 표시된다.
3. **Given** 구독 중인 회원, **When** 구독이 필요한 기능에 접근하면, **Then** 정상적으로 이용할 수 있다.

---

### User Story 7 - 문의 작성과 관리자 답변 권한 통제 (Priority: P3)

회원이 문의(질문)를 작성하고 관리자가 답변하며, 답변이 등록된 이후에는 회원이 해당 문의를 수정·삭제할 수 없다. 회원은 다른 회원의 작성 내용에 접근할 수 없다.

**Why this priority**: 문의 응대는 운영 지원 기능으로, 핵심 작성·다운로드 흐름이 갖춰진 뒤에 추가되어도 서비스 가치 검증에는 지장이 없다.

**Independent Test**: 한 회원이 문의를 작성해 수정·삭제되는 것을 확인하고, 관리자가 답변한 뒤에는 동일 문의의 수정·삭제가 차단되는 것을 확인하며, 다른 회원 계정으로 첫 번째 회원의 작성 내용에 접근이 차단되는지 확인하는 것만으로 완전히 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 문의(질문)를 작성하면, **Then** 관리자만 해당 문의에 답변을 작성할 수 있다.
2. **Given** 관리자가 아직 답변하지 않은 문의, **When** 작성자 회원이 문의를 수정하거나 삭제하면, **Then** 정상적으로 처리된다.
3. **Given** 관리자가 답변을 등록한 문의, **When** 작성자 회원이 해당 문의를 수정하거나 삭제하려 하면, **Then** 시스템은 이를 차단한다.
4. **Given** 회원 A가 작성한 계획서 또는 문의, **When** 다른 회원 B가 이를 조회·수정·삭제하려 시도하면, **Then** 시스템은 접근을 차단한다.

### Edge Cases

- 나라장터 API 인증값이 만료되었거나 API 응답이 실패하면 시스템은 어떻게 안내하는가?
- 선택한 공고에 안전보건관리계획서 샘플·표준 양식이 첨부되어 있지 않으면 어떻게 처리하는가?
- 작성 중이던 계획서 세션이 만료되면 입력해 둔 내용은 어떻게 되는가?
- 구독이 만료된 회원이 이미 작성 중이던 계획서에 접근하려 하면 어떻게 되는가?
- 관리자가 이미 등록된 발주처의 API 인증 정보를 중복 등록하려 하면 어떻게 되는가?
- 회원이 관리자가 이미 답변한 문의를 삭제하려고 API를 직접 호출하는 등 우회 시도를 하면 어떻게 되는가?
- 비회원이 계획서 작성·다운로드 화면 URL로 직접 접근(딥링크)하면 어떻게 되는가?
- 관리자 계정이 회원 관리 화면에서 다른 관리자 계정의 권한을 변경하려 하면 어떻게 되는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 비회원이 이메일, 비밀번호, 소속 건설사명, 사업자등록번호, 담당자명, 연락처를 모두 입력하여 회원가입할 수 있게 해야 하며, 이 항목 중 하나라도 누락되면 가입을 완료할 수 없게 해야 한다.
- **FR-002**: 시스템은 회원이 로그인 및 로그아웃할 수 있게 해야 한다.
- **FR-003**: 시스템은 비회원이 보호된 화면(계획서 작성, 다운로드, 내 문서함, 문의 등)에 접근을 시도하면 로그인 안내 화면을 표시하고, 보호된 화면의 실제 내용을 노출하지 않아야 한다.
- **FR-004**: 시스템은 회원이 자신이 작성한 안전보건관리계획서와 문의만 조회·수정·삭제할 수 있게 하고, 다른 회원이 작성한 내용에는 접근을 차단해야 한다.
- **FR-005**: 시스템은 관리자가 등록한 API 인증 정보를 사용해 나라장터에서 실제 입찰 공고문을 조회할 수 있게 해야 한다.
- **FR-006**: 시스템은 조회된 공고에 첨부된 안전보건관리계획서 샘플·표준 양식을 식별하여 회원에게 제시해야 한다.
- **FR-007**: 시스템은 발주처마다 서로 다른 공공데이터 API 인증 체계가 존재할 수 있다는 전제 하에, 관리자가 발주처 단위로 각기 다른 API 인증 정보를 개별 등록·수정·삭제할 수 있게 해야 한다.
- **FR-008**: 시스템은 회원이 선택한 공고가 요구하는 항목에 맞춰 안전보건관리계획서를 단계별(마법사 형태)로 작성할 수 있게 해야 한다.
- **FR-009**: 시스템은 계획서 작성의 각 단계에서 메인 화면 및 다른 단계와 일관된 화면 구조와 상호작용 패턴을 유지해야 한다.
- **FR-010**: 시스템은 작성 중인 계획서의 입력 내용과 진행 단계를 저장하여, 회원이 나중에 다시 접속해도 이어서 작성할 수 있게 해야 한다.
- **FR-011**: 시스템은 작성이 완료된 계획서를 PDF와 DOCX 두 형식으로 다운로드할 수 있게 해야 한다.
- **FR-012**: 시스템은 관리자가 로그인하여 전체 회원 목록을 조회하고 회원 계정 상태(예: 정상, 정지)를 관리할 수 있게 해야 한다.
- **FR-013**: 시스템은 관리자만 발주처별 API 인증 정보를 등록·수정·삭제할 수 있게 하고, 일반 회원의 접근은 차단해야 한다.
- **FR-014**: 시스템은 관리자가 안전보건관리계획서 서비스의 구독료 결제 화면(결제창)을 설정하고 관리할 수 있게 해야 한다.
- **FR-015**: 시스템은 회원의 구독 상태를 확인하여, 구독하지 않은 회원은 로그인 이후에도 공고 검색·계획서 작성·다운로드 등 핵심 기능 대부분에 접근할 수 없게 하고 구독(결제) 안내 화면으로 전환해야 한다.
- **FR-016**: 시스템은 회원이 문의(질문)를 작성할 수 있게 해야 한다.
- **FR-017**: 시스템은 관리자만 회원의 문의에 답변을 작성할 수 있게 하고, 일반 회원은 답변을 작성할 수 없게 해야 한다.
- **FR-018**: 시스템은 관리자가 답변을 등록한 문의에 대해서는 작성 회원이 더 이상 해당 문의를 수정하거나 삭제할 수 없게 제한해야 한다.
- **FR-019**: 시스템은 관리자의 답변이 등록되기 전까지는 작성 회원이 자신의 문의를 수정하거나 삭제할 수 있게 해야 한다.
- **FR-020**: 시스템은 관리자 계정을 일반 회원가입 절차와 완전히 분리하여, 시스템 운영자가 사전에 직접 생성·발급하는 방식으로만 관리해야 한다. 관리자는 일반 회원가입 화면을 통해 생성될 수 없으며, 일반 회원 로그인과 구분되는 방법으로 로그인해야 한다.
- **FR-021**: 시스템은 나라장터 API 인증 정보를 소스 코드나 화면에 노출하지 않고 관리자 전용 관리 화면을 통해서만 등록·조회할 수 있게 해야 한다.
- **FR-022**: 시스템은 좁은 화면(모바일 폭)에서 상단 내비게이션 메뉴를 햄버거 아이콘으로 축약하고, 이를 탭하면 공고검색·내 문서함·이용방법 등 전체 내비게이션 항목을 드로어(또는 오버레이) 형태로 노출해야 한다. 헤더의 로고와 주요 CTA 버튼은 축약 상태에서도 항상 노출되어야 한다.
- **FR-023**: 시스템은 회원과 관리자에게 등록된 발주처의 전체 공고 목록을 동일한 범위로 제공해야 하며, 관리자 화면에는 추가로 각 발주처 API의 최근 연동 상태(성공/실패)와 마지막 조회 시각을 함께 표시해야 한다.

### Key Entities *(include if feature involves data)*

- **회원(Member)**: 서비스에 가입한 사용자. 이메일, 비밀번호(해시), 소속 건설사명, 사업자등록번호, 담당자명, 연락처, 역할(회원/관리자), 가입일, 계정 상태를 가진다.
- **관리자(Admin)**: 회원 관리, 발주처 API 인증 정보 관리, 구독 결제 관리, 문의 답변 권한을 가진 특수 역할.
- **공고(Announcement)**: 나라장터에서 조회한 입찰 공고. 공고명, 발주처, 공고번호, 입찰마감일, 첨부 서식 목록을 가진다.
- **발주처(Ordering Agency)**: 공고를 발주하는 공공기관. 자체 요구 양식과 연결된 API 인증 정보를 가질 수 있다.
- **API 인증 정보(Procurement API Credential)**: 관리자가 등록한 발주처별 나라장터 API 인증값. 발주처, 인증키, 등록일, 상태(활성/비활성), 최근 연동 상태(성공/실패), 마지막 조회 시각을 가진다.
- **안전보건관리계획서(Safety Plan Document)**: 회원이 작성 중이거나 완료한 계획서. 연결된 공고, 작성자(회원), 진행 단계, 작성 항목 내용, 상태(작성중/완료)를 가진다.
- **구독(Subscription)**: 회원의 유료 이용 상태. 회원, 구독 시작일·만료일, 상태(활성/만료)를 가진다.
- **결제(Payment)**: 구독료 결제 트랜잭션. 회원, 구독, 결제일, 금액, 결과(성공/실패)를 가진다.
- **문의(Inquiry)**: 회원이 작성한 질문. 작성자(회원), 내용, 답변 내용, 답변 여부(잠금 여부), 작성일을 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 신규 사용자는 회원가입 시작부터 첫 공고 검색 결과 확인까지 5분 이내에 완료할 수 있다.
- **SC-002**: 회원 계정 간 접근 격리 테스트에서 다른 회원의 작성 내용(계획서·문의)에 대한 무단 조회·수정·삭제 시도는 100% 차단된다.
- **SC-003**: 회원은 요구 항목이 반영된 공고를 선택한 뒤 10분 이내에 계획서 단계별 작성을 완료할 수 있다.
- **SC-004**: 완성된 계획서는 다운로드 요청 후 10초 이내에 PDF 또는 DOCX 파일로 제공된다.
- **SC-005**: 관리자는 신규 발주처의 API 인증 정보를 5분 이내에 등록하여 해당 발주처 공고를 검색 결과에 반영할 수 있다.
- **SC-006**: 비회원의 보호된 화면 접근 시도는 100% 로그인 안내로 전환되며, 보호된 콘텐츠는 노출되지 않는다.
- **SC-007**: 관리자가 답변을 등록한 문의에 대한 회원의 수정·삭제 시도는 100% 차단된다.
- **SC-008**: 계획서 작성 화면 전 단계에 걸쳐 사용자 만족도 조사에서 "화면이 일관되게 느껴진다"는 응답 비율이 90% 이상이다.

## Assumptions

- 회원은 이메일·비밀번호 기반으로 스스로 가입·로그인하며, 관리자 계정은 회원가입 절차와 분리되어 시스템 운영자가 사전에 직접 생성·발급한다(회원의 관리자 승격 절차는 이번 범위에 포함하지 않는다).
- 나라장터 등 공공데이터 API 인증값은 이미 발급받아 보유하고 있으며, 이 기능은 해당 인증값을 시스템에 등록·활용하는 것을 전제로 한다(신규 인증값 발급 절차는 범위 밖). 발주처마다 인증 체계가 다를 수 있어 관리자는 발주처 단위로 API 인증 정보를 개별 등록·관리한다.
- 구독료 결제는 서비스 전체 이용을 기준으로 하며, 구독하지 않은 회원은 로그인 이후에도 공고 검색·계획서 작성·다운로드 등 핵심 기능 대부분에 접근할 수 없다.
- "일반 회원"은 관리자가 아닌 모든 회원을 의미하며, 별도의 중간 등급(예: 우수회원)은 이번 범위에 포함하지 않는다.
- 문의(질문)와 답변은 회원이 작성한 안전보건관리계획서 내용과는 별개의 1:1 지원 문의 게시판으로 간주한다.
- 구독료 결제는 표준적인 온라인 카드 결제 등 통상적인 결제 수단을 지원하는 결제창을 통해 처리되며, 세부 결제대행사(PG) 선정은 이번 범위 밖이다.
- 모바일 대응은 메인 화면과 동일한 반응형 수준을 유지하며, 좁은 화면의 내비게이션은 FR-022의 햄버거+드로어 패턴을 따른다. 별도의 네이티브 앱은 이번 범위 밖이다.

## Additional Clarifications (2026-08-29)

### Session Timeout & Account Recovery

- **Password Reset**: 회원이 로그인 화면에서 "비밀번호 찾기" 또는 "비밀번호 재설정"을 선택하면, 시스템은 등록된 이메일로 재설정 링크를 발송한다. 재설정 링크는 24시간 유효하며, 시간 만료 후에는 새로 요청해야 한다.
- **Session Timeout**: 회원이 마지막 작업(클릭, 입력, 스크롤 등)을 수행한 후 30분 이상 인터랙션이 없으면, 시스템은 세션을 자동으로 만료시키고 로그인 화면으로 리다이렉트한다. 만료 2분 전에 "세션이 곧 만료됩니다" 경고를 표시할 수 있다.
- **Account Lockout**: 로그인 실패를 5회 이상 반복하면, 해당 이메일 계정은 15분간 로그인 시도가 차단된다.

### Document Persistence & Auto-Save

- **Auto-Save Strategy**: 계획서 작성 마법사의 각 단계에서 사용자가 입력한 데이터는 15초 간격으로 자동 저장된다. Phase 1(Mock)에서는 localStorage에, Phase 2(Supabase)에서는 PostgreSQL의 documents 테이블에 저장된다.
- **Unsaved Data Warning**: 사용자가 저장하지 않은 채로 화면을 떠나려고 하면 (브라우저 탭 닫기, 페이지 새로고침 등), "저장하지 않은 변경사항이 있습니다. 정말 떠나시겠습니까?" 경고 대화상자가 표시된다.
- **Session Expiry During Edit**: 작성 중 세션이 만료되면, 최종 저장된 데이터는 유지되며, 사용자가 다시 로그인하면 마지막 저장 지점부터 계속 작성할 수 있다.

### PDF & DOCX Generation

- **Generation Approach**: Phase 1에서는 PDF/DOCX 다운로드 버튼이 UI 상에만 존재하며, 실제 파일 생성은 구현 범위 밖이다. Phase 2 이후 별도 작업으로 다음 중 하나의 방식을 선택한다:
  - **Client-Side**: JavaScript 라이브러리(예: pdfkit, docx)를 이용해 브라우저에서 직접 생성.
  - **Backend Service**: API 엔드포인트를 통해 서버에서 생성 후 다운로드 제공.
  - **Third-Party Service**: Supabase Edge Functions 또는 별도 SaaS(예: Document Generation API)를 이용.
- **Download Timing**: SC-004에서 정의한 "10초 이내"는 파일 생성(10KB-5MB 범위) + 다운로드 시작까지의 시간을 의미한다.

### Expired Subscription Access to Existing Documents

- **Subscription Expiry**: 회원의 구독이 만료되면, 향후 공고 검색·계획서 작성·신규 다운로드는 차단되며 구독 안내 화면으로 전환된다.
- **Read-Only Access to Completed Plans**: 이미 완료된 계획서(status='completed')에 대해서는 만료된 회원도 조회·다운로드할 수 있다. 단, 작성중인 계획서(status='in_progress')에 대해서는 만료 후 편집 불가(읽기 전용 또는 접근 차단).
- **Reactivation**: 구독을 재개하면, 이전 진행 중이던 계획서(status='in_progress')에서 중단한 지점부터 계속 작성할 수 있다.

### Wizard Step Variability

- **Fixed 4-Step Design (Phase 1)**: 현재 Claude Design 화면 기준으로 안전보건관리계획서 작성 마법사는 정확히 4개 단계로 고정된다:
  1. 공고 정보 확인
  2. 공고 분석 결과 검토
  3. 계획서 입력 폼
  4. 다운로드 옵션
- **Future Variable Steps (Phase 2+)**: 향후 공고마다 다른 요구 항목을 반영할 때, 단계 수가 가변적으로 변할 수 있도록 설계하되, Phase 1 구현 시점에는 4단계 고정으로 진행한다.
- **Dynamic Step Indicator**: 각 단계 상단에 "1/4", "2/4", "3/4", "4/4" 형식의 진행 인디케이터를 표시한다.
